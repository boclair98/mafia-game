> 한 명이 죽었다. 범인은 아직 이 방 안에 있다.

**검은 자정(Black Midnight)**은 마피아 게임의 사회적 심리전과 살인사건 기록 추리를 결합한 실시간 소셜 추리 게임입니다. 플레이어는 밤의 비밀 행동, 새벽에 도착한 현장 단서, 낮의 음성 토론과 공개 투표를 대조해 범인을 찾아냅니다.

별도 설치나 회원가입 없이 브라우저에서 바로 플레이할 수 있고, 친구 방·AI 혼자 수사·초보자용 첫 사건을 모두 제공합니다.

이번 개편의 중심은 **밤의 확정 결과 → 공식 진술 → 근거를 인용한 질문 → 해명·판단 수정 → 투표 → 종료 후 복기**입니다. `증언 대조실`은 누군가의 말과 공개 기록을 나란히 읽고 질문하게 합니다. 질문이나 해명을 자동 유죄 판정으로 바꾸지 않으며, 봇도 자신에게 허용된 정보로 판단합니다. 기존 수사관 패스포트는 로그인한 플레이어의 완주 사건·XP·일일 목표·배지를 저장합니다.

## 2026-11-22 증언·증거 연결 개편

### 후속: 경기 복구와 음성 재연결

- `ROOM_PERSISTENCE_ENABLED=true`인 운영·compose에서는 PostgreSQL에 서버 전용 경기 체크포인트를 저장합니다. 진행 중 경기의 같은 좌석으로 복귀하면 역할·단계·확정 행동을 복원합니다. 중단 시간 동안 단계를 몰아서 진행하지 않습니다.
- DB 실행권/epoch fencing과 방 변경 잠금으로 겹친 프로세스의 중복 진행을 차단합니다. 저장 뒤 상태를 전송하며, 저장 실패는 재접속이 필요한 미확정 결과로 취급합니다. 이는 수평 확장이나 무중단 배포 보장이 아닙니다.
- WebSocket heartbeat·온라인/탭 복귀·오래된 이벤트 차단을 추가합니다. 음성은 제한된 자동 재협상, 실제 연결/RTP 수신 상태, 재생 허용과 수동 재연결을 제공합니다. 대기실은 연결 해제 시 좌석을 반납하므로 진행 중 경기의 좌석 복구와 구분합니다.
- 선택적 TURN 서버 설정은 단기 자격증명을 게임 WebSocket에서 발급합니다. 이번 무료 배포에는 TURN 서버가 없으며 일부 회사망·통신사망의 연결을 보장하지 않습니다.
- **최대 동시접속 4만 명은 장기 목표이며 이번 검증 결과가 아닙니다.** 사용자가 무료 범위를 선택했고 별도 fleet/중계망/분산 부하 발생기를 준비하지 않았습니다. 실제 측정 범위는 [부하 검사](docs/CAPACITY_TEST.md), 실패/복구 계약은 [복구 설계](docs/RESILIENCE.md)를 확인하세요.

- **실제 밤의 결과:** 마지막으로 확정된 습격·치료·조사·경호 선택을 서버 전용 기록으로 고정합니다. 진행 중에는 사망·구조 등 공개 가능한 결과만 `night_summary`로 보내고, 실제 행동자와 대상의 전체 기록은 `gameover`의 `night_replay`에서 공개합니다.
- **기록을 제시하는 질문:** 현재 낮의 다른 생존자 공식 진술과 공개 감식 단서 또는 이번 밤의 결과 보고를 선택해 질문합니다. 질문 대상은 서버가 진술 작성자로부터 결정합니다. 상대는 설명하거나 판단을 수정할 수 있으며 두 내용은 인용 원문과 함께 남습니다.
- **공정한 봇의 정보 범위:** 봇은 규칙·템플릿·성향·공개 기록과 자신의 정당한 개인 조사 결과를 사용합니다. 시민 봇이 숨은 역할이나 다른 탐정의 비공개 결과를 읽지 않게 했습니다. 자유 문장의 진위를 이해하는 외부 LLM은 연결하지 않았고 유료 모델 호출도 없습니다.
- **읽을 수 있는 타임라인:** 실제 정산 단계의 가시적인 순서와 같은 밤의 기록 연결을 사용합니다. 같은 내용에 서로 다른 숨은 정답을 주는 퍼즐이 아닙니다. 결과 anchor는 모두에게 제공하며, 다른 밤의 단서·조각을 결합한 제출은 거부합니다.
- **정보와 상태의 정직한 표현:** 초기 개인 packet은 검증되지 않은 제보로 표시합니다. 질문·답변의 접수는 서버 state로 확인하며 입력·전송 중·오류·결과 미확정을 구분합니다. 사건 기록 기여자는 공식 진술 횟수 기준이며 실제 설득력 투표 결과가 아닙니다.
- **읽기 중심의 게임 UI:** 증언·근거·질문의 우선순위, 단계별 주 행동, 모바일 탐색을 정리합니다. Pretendard v1.3.9를 OFL 라이선스와 함께 자체 제공하며 폰트 CDN이나 빌드 시 원격 폰트 요청에 의존하지 않습니다.

설계 선택과 시각 기준은 [design.md](design.md), 데이터·프로토콜은 [아키텍처 설계](docs/ARCHITECTURE.md), 검사와 독립 반론은 [2026-11-22 검증 기록](docs/QA_2026_11_22.md)에 정리했습니다. 구현·단위/통합 검증·브라우저 검증·운영 확인·실사용자의 재미와 재방문은 각각 별도의 증거입니다.

## 이전 검증 기록: 2026-10-11 디자인·실시간 개선

- **첫 화면:** 비 오는 수사실, 절제된 금색·버건디와 명확한 첫 사건 CTA. 친구·AI 7명·입문 AI 3명 모드와 방 코드 참가를 구분합니다. 명예의 전당과 패스포트는 실제 기능 이름으로 안내합니다.
- **게임 HUD:** 현재 단계·서버 기준 남은 시간·행동이 우선 보입니다. 모바일 사건/수사/대화/내 정보 탭과 44px 터치 영역, 읽기 쉬운 본문을 적용했습니다. 전환 연출은 1.8초이며 긴 라운드 전체 화면 연출을 없애 상시 안내 카드로 확인합니다.
- **대화:** 한글 조합 중 Enter를 전송하지 않습니다. 이전 대화를 읽을 때 강제 이동하지 않으며 최신 대화 버튼을 제공합니다. 사망자와 관전자는 유령 비밀 채널에서 대화합니다. 생존자에게 이 메시지·음성 채널을 전달하지 않습니다.
- **선택:** 피고 지목과 최종 처형/석방을 구분합니다. 기권도 제출한 표로 집계하되 피고 후보 계산에서는 제외합니다. 표시되는 공개 반응 점수는 범인 확률이 아닙니다.
- **연결·권한:** 새 연결만 기존 좌석을 제어합니다. 중복 탭의 이전 연결은 종료하고 자동 재접속 경쟁을 멈춥니다. 방장이 없는 경우 복귀한 기존 참가자가 방장을 맡아 재경기를 시작할 수 있습니다. 연결된 다른 방장은 유지하고 관전자는 승격하지 않습니다. 없는 방·만석·혼자 전용 방의 오류가 실제 브라우저 close 프레임으로 전달됩니다.
- **상태 동기화:** 매 단계 `phase_id`를 새로 만들고 밤 행동·투표·판결에서 검증합니다. 서버 마감 이후 및 지난 단계 요청은 거부합니다. `server_now`와 브라우저 monotonic 경과 시간으로 기기 시계 변경 영향을 줄입니다. 전송과 서버 접수를 구분합니다.
- **음성:** `voice_scope`와 개인별 허용 참가자만 연결합니다. 단계·채널 변경 때 기존 peer·수신 미디어·ICE 큐를 정리하고 오래된 신호를 거부합니다. P2P의 악성 클라이언트 미디어 통제에는 SFU가 필요합니다.
- **초기 다운로드:** 서비스워커 설치 때 모든 장면 이미지를 미리 받지 않고, 방문한 이미지부터 캐시합니다. 기존 자산·로그인·기록·DB 스키마는 유지합니다.

위 이전 릴리스에서 서버 장애 복구는 제공하지 않았습니다. 현재 후속 변경의 PostgreSQL 복구 범위는 위 절과 [아키텍처 설계](docs/ARCHITECTURE.md)를 참고하세요. 추가 직업 10종, 전지적 유령 관전, 실제 TURN/SFU 운영은 여전히 제공하지 않습니다. 전체 역할은 경기 종료 후 공개합니다.

검증: 게임/WS/추리 회귀 116개와 WebRTC scope 회귀 3개를 통과했습니다. 로컬 5방×8명(40연결) 65.91초 부하에서 채팅 1,282/1,282건 접수, 2,550 pong, 오류 0, 재접속 1건과 연결 종료 후 0.20초 내 방/연결 0을 확인했습니다. 동일 머신 ping 왕복 p50 16ms·p95 328ms이며 게임 행동 ACK 지연이나 운영 수용 인원을 뜻하지 않습니다. 동시 burst 측정은 p95 500–719ms여서 추가 성능 개선이 필요합니다. 실제 마이크 송수신·1,000명 부하·사람 3판의 사용성·실사용 p75 Web Vitals는 별도 검증이 필요합니다. PostgreSQL을 포함한 전체 백엔드 테스트와 프런트엔드 lint/build는 상단 CI 배지와 Actions에서 검증 결과를 확인할 수 있습니다.

## 기획 결정

검은 자정은 “말싸움에서 이기는 마피아”가 아니라 **사건 기록을 읽고 위험한 결론을 공개적으로 책임지는 플레이어**를 만드는 것을 목표로 합니다.

| 설계 질문 | 선택한 해법 | 플레이어가 느끼는 효과 |
| --- | --- | --- |
| 처음 온 사람은 무엇을 해야 하는가? | 첫 사건 모드, 단계별 진행관 문장, 중앙 카운트다운 | 규칙을 읽느라 첫 판을 놓치지 않음 |
| 단서가 장식처럼 보이지 않으려면? | 확정 밤 기록과 연결된 감식 후보·같은 밤의 기록 조각 | 어떤 결과를 근거로 질문했는지 설명 가능 |
| 상대의 주장을 어떻게 검토할까? | 공식 진술과 공개 기록을 함께 인용하는 증언 대조실 | 자신의 해석을 묻고 답변·판단 수정까지 확인 |
| 정보가 여러 패널에 흩어지지 않으려면? | 용의자 추론 맵에서 감식·공개 증거·가설·진술을 행 단위로 비교 | 투표 전에 조사 우선순위를 빠르게 정리 |
| 추리의 긴장감을 어떻게 공개할까? | 증거 연결 고리에 인장을 걸고 공개 선언 | 맞히면 보상, 틀리면 책임이 남음 |
| 혼자 플레이에서 설득이 의미 있으려면? | 공개 근거를 읽고 의심을 재검토하는 규칙 기반 봇 | 어떤 근거에 반응했는지 추적 가능 |
| 한 판 뒤에 왜 다시 할까? | 사건 등급·훈장·결정적 장면·사후 예측 | 다음 판에 개선할 목표가 생김 |

핵심 성공 기준은 기능 수가 아니라 다음 세 가지입니다.

1. 10분 안에 초보자가 “현재 단계와 내가 할 일”을 말할 수 있어야 합니다.
2. 게임 종료 후 승패의 이유를 사건 파일에서 다시 설명할 수 있어야 합니다.
3. 한 명은 AI 전용 사건을 시작하고, 친구들은 별도 파티 방에서 같은 핵심 규칙으로 플레이할 수 있어야 합니다. 진행 중인 solo 방에 친구가 합류하는 기능은 제공하지 않습니다.

위 항목은 설계·사용성 검증의 목표이며, 실제 사용자 연구로 달성했다고 확인한 지표는 아닙니다.

### 수사관 패스포트 (Retention Foundation)

게임이 끝날 때 서버가 로그인한 플레이어별 결과를 기록합니다. 안정된 match ID와 사용자별 중복 제약으로 같은 경기 결과 재처리를 구분합니다. 체크포인트와 결과 반영은 별도 트랜잭션이며, 복구 시 대기 중 결과를 재시도합니다. DB 자체 유실이나 외부 부수 효과까지 포괄하는 exactly-once 보장은 아닙니다. 다음 네 가지를 누적해 재방문에 필요한 기록을 제공합니다.

- **XP·레벨:** 참여, 타임라인 복원, 사회적 상호작용, 승리에 따라 서버에서 계산합니다.
- **일일 사건 목표:** 사건 완주·증거 연결·심문 기록을 매일 새로 제시합니다.
- **배지:** 첫 사건, 타임라인 분석, 소셜 추리, 솔로 완주, 연속 출석을 해금합니다.
- **사건 보관소:** 사건 코드·등급·점수·승리 팀·획득 XP를 최근 기록으로 다시 볼 수 있습니다.

패스포트 조회는 인증이 필요한 `GET /api/passport`이며, 브라우저가 XP나 배지를 직접 제출하는 쓰기 API는 제공하지 않습니다. 이 경계를 유지하면 추후 판매 가능한 상품을 프로필 테마·사건 파일 스킨·시즌 패스·호스트 편의 기능처럼 **비경쟁적(entitlement) 상품**으로 한정할 수 있습니다. 실제 결제·환불·구매 검증은 별도의 Stripe 또는 스토어 결제 연동 단계에서 서버 권위로 추가할 예정이며 현재는 결제 상품을 판매하지 않습니다.

## 왜 만들었는가

전통적인 마피아 게임은 대화와 투표의 긴장감이 강점이지만, 처음 온 플레이어는 다음 문제를 자주 겪습니다.

1. 지금 어떤 단계인지, 무엇을 해야 하는지 놓치기 쉽습니다.
2. 한 판이 끝나면 왜 그 사람이 범인이었는지 기록이 남지 않습니다.
3. 사람이 모이지 않으면 게임 자체를 시작하기 어렵습니다.
4. 단서가 장식처럼 느껴지면 추리가 결국 말싸움만 남습니다.

검은 자정은 이 문제를 다음 방식으로 해결합니다.

- 단계별 진행관 안내와 기본 아나운서 음성으로 현재 목표를 알려줍니다.
- 사건 기록에 질문·진술·압박·투표·최후 변론을 순서대로 남깁니다.
- 혼자 수사 모드에서 AI 용의자 7명이 빈 좌석을 채웁니다.
- 확정 밤 결과와 공식 진술을 함께 인용하는 질문을 제공합니다.
- 종료 시 사건 등급, 훈장, 결정적 장면과 전체 배역을 복기합니다.

## 핵심 경험

### 1. 마피아의 심리전

마피아는 밤마다 습격 대상을 고르고, 낮에는 시민인 척 알리바이를 세웁니다. 시민은 탐정·의사의 정보와 다른 사람의 말투, 침묵, 투표를 함께 해석해야 합니다.

### 2. 사건 파일을 완성하는 추리

실제 밤 정산에서 나온 감식 단서와 공개 결과, 각자가 공개한 미확인 제보·공식 진술이 사건 파일에 남습니다. **확인된 결과와 주장·제보의 신뢰 수준**을 구분하고 누가 언제 공개했는지도 함께 읽습니다.

낮과 투표 단계에서는 **용의자 추론 맵**이 핵심 화면으로 열립니다. 각 용의자에게 연결된 감식 단서, 플레이어 공개 증거, 봉인 가설, 공식 진술 횟수와 나의 신뢰·의심 표시를 한 행에서 비교합니다. 표시되는 위험도는 범인을 자동 판정하는 점수가 아니라, 공개된 신호를 얼마나 더 조사해야 하는지 보여 주는 우선순위입니다. 사용자는 같은 화면에서 개인 판단을 기록하고, 용의자를 집중 선택하거나 증거 연결 고리로 이동할 수 있습니다.

### 3. 혼자서도 시작되는 사건

혼자 수사 · AI 7명은 전용 solo 방을 만들고 AI 용의자를 채워 시작합니다. 봇은 규칙 기반 정책에 성향·일부 무작위 선택·최근 기억을 결합합니다. 자신의 조사 결과와 공개 기록을 읽어 질문·투표·판결을 결정하고, 인용된 근거에 따라 기존 의심을 재검토합니다. 외부 생성형 모델이나 자연어 진위 판정기는 아닙니다.

### 4. 친구와 함께 남는 기록

친구 방에서는 방 코드를 공유해 합류합니다. 종료 후 사건 파일을 텍스트로 복사하고 질문·답변·공식 진술 기여와 밤 행동 기록을 함께 복기할 수 있습니다. 서버가 영구 보관하는 전체 경기 영상이나 URL 기반 리플레이 서비스는 제공하지 않습니다.

## 게임 모드

### 친구와 함께

- 4~12명이 방 코드를 통해 합류합니다.
- 방장은 준비 상태를 확인하고 게임을 시작합니다.
- AI 좌석을 채워 인원이 부족한 상태에서도 테스트할 수 있습니다.
- 초대 링크에는 방 코드와 플레이 모드가 포함됩니다.

### 혼자 수사 · AI 7명

- 한 명의 사람 플레이어와 최대 7명의 AI 용의자로 구성됩니다.
- 별도 solo- 방이라 일반 파티 방과 섞이지 않습니다.
- AI마다 기록 분석가, 도발적인 심문관, 회의론자, 알리바이 중재자 등 다른 성향을 갖습니다.
- AI도 질문, 공식 진술, 압박, 익명 제보, 공개 맹세와 투표를 수행합니다.

### 첫 사건 · 8~12분

- 마피아·의사·탐정·시민만 사용하는 4석 guided 모드입니다.
- 역할 설명, 밤 행동, 첫 단서, 투표의 의미를 진행관이 단계별로 안내합니다.
- 처음 접한 플레이어가 한 판 안에 규칙과 추리 흐름을 익히는 것을 목표로 합니다.

## 한 판의 흐름

~~~text
대기실 입장
    ↓
역할·미확인 개인 제보 확인
    ↓
밤: 마피아 습격 / 의사 치료 / 탐정 조사 / 경호
    ↓
새벽: 피해 결과·현장 감식 단서·진행관 브리핑
    ↓
낮: 음성 토론·공식 진술·공개 기록을 인용한 질문과 답변
    ↓
긴급 지목·익명 제보·공개 투표
    ↓
최후 변론·처형 또는 석방 판결
    ↓
승패 확인·사건 리포트·사후 예측 결과와 실제 밤 행동 복기
~~~

단계 전환마다 화면 중앙에 알림과 남은 시간이 표시됩니다. 기본 아나운서 음성도 같은 전환을 읽어 주므로, 화면을 잠시 보지 못한 플레이어도 현재 사건 진행을 따라갈 수 있습니다.

### 초보자에게 보이는 시간 약속

| 모드 | 구성 | 안내하는 목표 시간 | 목적 |
| --- | --- | --- | --- |
| 첫 사건 | 사람 1명 + AI 3명, 기본 4역할 | 약 8~12분 | 규칙과 추리 문법 학습 |
| 퀵 파티 | 사람 4~12명, AI 좌석 선택 | 약 20~25분 | 친구와 빠르게 한 판 |
| 클래식 파티 | 사람 6~12명, 긴 토론 | 35분 이상 | 역할 심리전과 리플레이 |
| 솔로 사건 | 사람 1명 + AI 7명 | 약 20~30분 | 혼자서도 완결된 사건 경험 |

각 단계는 타이머가 끝나면 자동으로 넘어가지만, 화면을 읽지 못한 순간을 위해 중앙 알림·현재 목표·아나운서 음성을 같은 문장으로 유지합니다. 사용자는 “지금 무엇을 해야 하는지”를 매번 한 줄로 확인할 수 있습니다.

위 시간은 모드 안내를 위한 대략적인 목표입니다. 진영 승리 시점·토론·조기 진행에 따라 달라지며 실제 사용자의 완주 시간 분포를 측정한 값은 아닙니다.

## 추리 시스템

### 밤의 기록과 타임라인

서버는 각 밤의 마지막 선택을 정산하고 다음 단계의 기록 조각을 만듭니다.

~~~text
능력 선택 → 행동 마감 → 실제 정산 결과 → 개인 결과 전달 → 공개 사건 보고
~~~

타임라인의 시간 표시는 `밤 · 01`, `새벽 · 05`처럼 읽기 위한 정산 단계입니다. 실제 플레이어의 이동 경로나 물리적 범행 시각을 측정한 로그가 아닙니다. 각자 일부 조각을 받되 이번 밤의 결과 anchor는 모두에게 제공됩니다. 가시적인 단계의 순서·인접 관계를 복원하고, 같은 밤의 단서와 연결해 자신의 가설을 설명할 수 있습니다.

이 버전은 숨겨진 인과 순서를 맞히는 별도 추리 퍼즐을 제공한다고 주장하지 않습니다. 무작위 레이아웃 때문에 동일한 증거에 다른 정답이 붙던 구조를 제거했으며, 제출 직후 숨은 전체 정답을 알려 주지도 않습니다.

### 증언 대조실

낮에는 다른 생존자가 남긴 **공식 진술 + 공개 감식 단서 또는 이번 밤의 결과 보고**를 선택해 한 번 질문할 수 있습니다. 확인된 습격이 없는 조용한 밤에도 실제 결과 보고를 인용할 수 있습니다. 상대는 `주장 설명` 또는 `판단 수정`과 답변을 남깁니다.

- 질문의 대상은 진술 ID로부터 서버가 결정합니다. 클라이언트가 임의의 사람을 진술 작성자로 바꿀 수 없습니다.
- 인용한 진술·기록은 질문에 복사해 보관하므로 원본의 보관 한도가 지나도 해당 질문의 문맥이 사라지지 않습니다.
- 동일한 내용의 재전송은 새 질문이나 답변을 만들지 않습니다. 다른 두 번째 제출, 타인의 답변, 지난 단계·마감 이후 요청은 거부합니다.
- 자유 문장의 진위를 자동 판정하지 않습니다. 질문이 많이 달렸거나 판단을 수정했다는 사실만으로 유죄 또는 거짓말이 확정되지 않습니다.
- 봇의 답변은 인용된 공개 후보와 자신의 기존 판단을 사용합니다. 근거가 기존 지목을 뒷받침하지 않으면 의심을 재검토할 수 있으며, 이 과정이 다음 선택의 근거에 반영됩니다.

### 증거 연결 고리 (Chain of Evidence)

검은 자정의 차별화된 핵심 루프입니다. 낮마다 생존자는 **용의자 1명 + 공개 감식 단서 1개 + 자신만 받은 시간 조각 1개**를 하나의 가설로 봉인할 수 있습니다. 한 판에 지급되는 증거 인장 2개 중 1~2개를 걸기 때문에, 확신이 클수록 보상도 커지지만 틀렸을 때 잃는 점수도 커집니다.

가설의 선택 내용은 즉시 공개 보드에 올라가지만, 세 연결이 실제 사건과 맞는지는 서버에만 보관됩니다.

- 선택한 용의자가 인용한 밤의 실제 습격에 참여했는가
- 선택한 감식 단서의 후보 범위에 그 용의자가 포함되는가
- 선택한 기록 조각과 감식 단서가 같은 확정 밤 사건에 속하는가

따라서 공개 단서는 일부러 미끼를 선택할 수도 있습니다. 다른 사람이 이미 봉인한 고리와 겹치더라도, 사건이 끝날 때까지 누가 진짜 연결을 잡았는지 알 수 없습니다.

사건이 종료되면 서버가 용의자·단서·기록의 3개 연결을 `완전 적중`, `부분 적중`, `연결 붕괴`로 검증합니다. 결과는 점수·훈장·사건 리포트에 반영됩니다. 정확성은 종료 전 공개하지 않으며 가설을 제출했다는 사실과 확정 정답을 구분합니다.

이 연결은 **같은 밤의 기록과 용의자를 묶는 가설**입니다. 한 장의 특정 카드 소유 운을 정답 조건으로 삼지 않습니다. 다른 밤의 단서와 현재 조각을 결합하면 서버가 제출을 거부하며, 현재 조각과 연결할 감식 단서가 없는 낮에는 증거 고리 제출을 안내하지 않습니다. 질문·가설·기록은 방 상태이며 운영 체크포인트로 복구할 수 있지만, 만료 후에도 다시 재생하는 영구 사건 리플레이는 아닙니다.

### 사건 프로필

호텔, 야간열차, 미술관, 관측소, 기록실, 송신탑, 유리온실, 라디오국, 여객선, 극장, 지하철, 산장 등 **15개의 사건 프로필** 중 하나가 무작위로 선택됩니다. 현장·피해자·브리핑 문구·표면 단서는 달라지지만, 초보자가 이해할 수 있도록 추리의 기본 문법은 유지합니다.

### 미확인 개인 제보

시작 시 받는 개인 packet은 첫날의 대화를 위한 미확인 제보입니다. 실제 밤 행동 전 생성되므로 이동·범행을 관찰한 확정 증거가 아닙니다. 낮에 공개할 수 있고, 마피아의 위조 제보도 같은 형식을 사용합니다. 화면과 본문에 미확인 상태를 명시하며 실제 정산에서 만들어진 `night_summary`·감식 단서와 구분합니다.

### 라운드 사건 카드

매 라운드 붉은 실, 기록실 정전, 마지막 통화, 교차 심문 중 하나가 적용됩니다. 예를 들어 기록실 정전에서는 긴급 지목이 봉인되었다가 시민 투표가 시작될 때 공개됩니다.

### 긴급 지목과 익명 제보

생존자는 낮마다 한 번 특정 용의자를 공개적으로 압박할 수 있습니다. 별도로 한 문장의 익명 제보를 봉인할 수 있습니다. 제보 작성자는 공개되지 않으므로, 도움이 되는 목격 정보인지 마피아가 흘린 미끼인지 다른 기록과 비교해야 합니다.

### 공개 맹세와 비밀 계약

- **공개 맹세:** 다음 투표에서의 행동을 모두에게 약속합니다. 투표 후 약속을 지켰는지가 사건 파일에 남습니다.
- **비밀 계약:** 특정 플레이어에게만 한 줄 동맹을 제안하고 수락·거절을 기록합니다. 자유 문장의 약속 이행·배신을 자동 검증하지 않으며 관계 기억은 현재 경기 안에서만 유지됩니다.

두 메커니즘은 같은 대화를 서로 다른 공개 범위로 나눠, “누구에게 어떤 말을 했는가” 자체를 단서로 만듭니다.

### 사망자와 사후 수사

사망한 시민 측 플레이어는 생존자의 공개 대화에 다시 개입하지 못하지만 사건 파일은 계속 읽을 수 있습니다. 살아 있는 용의자 한 명을 최종 범인으로 봉인해 사후 예측을 남길 수 있고, 게임 종료 뒤 적중 여부가 개인 기록에 표시됩니다.

### 사건 종료 리포트

종료 시 추리 연결, 압박 적중, 공개 진술, 타임라인 결과를 종합해 S/A/B/C 등급과 사건 훈장을 계산합니다. `사건 기록 기여자`는 공식 진술 횟수에 따른 표시이며 다른 사람의 설득력 투표나 실제 여론 변화 측정값이 아닙니다. `밤의 실제 기록`은 종료 때만 행동자·역할·최종 대상·정산 결과를 공개합니다. 질문에 인용된 주장·기록·답변을 함께 읽어 자신의 판단을 복기할 수 있습니다.

## 모바일과 데스크톱 UX

모바일 화면을 데스크톱 UI의 축소판으로 만들지 않고, 단계에 맞는 정보 우선순위를 별도로 제공합니다.

| 화면 영역 | 제공 정보 |
| --- | --- |
| 사건 | 현장 단서, 공개 증거, 현재 수사 지령, 타임라인 |
| 수사 | 용의자 카드, 의심도, 질문, 긴급 지목, 투표·밤 행동 |
| 대화 | WebRTC 음성 채팅, 공개·비밀 채팅, 빠른 반응 |
| 내 정보 | 역할, 개인 증거, 조사 결과, 개인 추리 보드, 사후 수사 |

데스크톱에서는 용의자 목록만 내부 스크롤되고 조사·투표 명령 바는 테이블 하단에 고정됩니다. 사건 배너의 지휘 HUD는 `현재 단계 → 지금 해야 할 일 → 다음 단계`를 한 줄로 보여주고, 바로가기 버튼으로 필요한 패널에 이동합니다. 모바일에서는 하단 고정 명령 dock이 현재 단계의 핵심 행동을 계속 노출하며, 새벽에는 타임라인 복원 버튼을 바로 제공합니다.

타임라인·증거 고리·공개 맹세·비밀 계약은 **수사 도구 작업대** 안에서 탭으로 전환합니다. 필요한 도구 하나만 펼치므로 기능이 늘어나도 용의자 목록과 핵심 행동이 화면 아래로 밀리지 않습니다.

초기 로딩을 위해 시네마틱 배경은 원본 PNG 약 3.8MB 대신 동일 해상도의 WebP 약 273KB를 사용합니다. 화면 밖 랜딩 섹션은 `content-visibility`로 렌더링을 미루고, 게임 타이머는 초 단위 UI에 맞춰 초당 한 번만 갱신합니다. 숨겨진 탭에서는 랜딩 연출과 상태 폴링을 일시 정지합니다.

지원 환경:

- 최신 Chrome, Edge, Safari, Firefox
- Android Chrome
- iPhone Safari
- 홈 화면 설치가 가능한 PWA
- Capacitor Android / iOS 셸

음성 채팅을 사용하려면 브라우저의 마이크 권한이 필요합니다. 진행관 음성은 브라우저의 한국어 speechSynthesis 음성을 사용하며, 사용자가 설정에서 끌 수 있습니다.

### 서버 권위 게임 상태

클라이언트는 action, vote, judge 같은 행동 요청만 보냅니다. 서버가 역할, 능력 충돌, 피해 결과, 단서 공개, 투표 집계, 승패를 검증한 뒤 참가자별로 필터링한 상태를 다시 보냅니다. 따라서 브라우저에서 다른 사람의 비밀 역할이나 탐정 결과를 임의로 읽는 구조가 아닙니다.

### 방과 데이터 수명

방·플레이어·밤 ledger·질문/답변·게임 진행 상태는 메모리에서 진행하며, 운영은 PostgreSQL의 비공개 체크포인트를 사용합니다. 현재 DB 실행권을 가진 단일 runtime만 진행하고 epoch가 지난 쓰기는 거부합니다. 저장한 상태로 같은 좌석의 진행 중 경기를 복구하며 중단 시간만큼 단계를 소진하지 않습니다. 복구 저장을 끈 로컬 메모리 모드와, 처음 적용하기 전 구 버전의 미저장 경기는 이 보장이 없습니다.

기본 24시간 비활성 체크포인트는 복구 대상에서 제외하고 다음 서버 정리 때 삭제합니다. 플랫폼이 zero-scale 상태면 실제 삭제 시점은 늦어질 수 있습니다. DB 자체 장애/유실·TTL 만료·호환되지 않는 스키마는 별도 실패이며 복구 키와 로그인 계정도 필요합니다. 이는 전체 밤 행동·대화를 영구 재생하는 서비스가 아닙니다.

### 4만 명 규모 운영 게이트

현재 코드는 한 인스턴스가 무제한으로 소켓을 받지 않도록 `MAX_CONNECTIONS`와 `MAX_ROOMS`를 제한하고 동일 snapshot을 반복 전송하지 않습니다. 상한은 측정된 수용 인원이 아닙니다. 과부하 `4006`은 화면 안내 후 수동 재시도, 실행권/저장소 복구 `4008`은 자동 재시도, 다른 로그인 계정의 좌석 `4009`는 다시 로그인 안내로 구분합니다. `/api/status`의 사용량은 현재 프로세스 범위이며 전체 fleet 합계가 아닙니다.

4만 명의 가입·방문 예상과 4만 명의 동시 접속은 다른 요구입니다. 현재 구현·설정값이나 이전의 소규모 로컬 측정은 어느 쪽의 운영 수용량도 입증하지 않습니다. 실제 다중 인스턴스 운영 전에는 다음 경계를 설계·검증해야 합니다.

1. 현재 단일 실행권을 넘어 방별 owner routing과 분산 fanout을 구현·검증해야 합니다. standby로 계속 라우팅되면 복구 재시도가 지연될 수 있습니다. Redis 설치나 replica 수 증가만으로 가용성·수용량이 보장되지 않습니다.
2. 음성의 NAT·모바일 네트워크에는 TURN, 미디어 중계·강제 발언 권한에는 SFU를 검토합니다. 대표 방/연결·입력·느린 클라이언트 부하와 장애 시험으로 replica 수·DB 연결 예산·WebSocket egress를 측정합니다.

이 저장소의 연결·방·버퍼 제한은 포화 지점을 제어하기 위한 기준선이며 실제 배포 환경에서 검증해야 합니다. 공유 상태 계층과 부하 테스트 없이 4만 동시 접속을 보장한다고 광고해서는 안 됩니다.

## 로컬 실행

### 권장: Docker Compose 한 번에 실행

요구 사항은 Docker Desktop입니다. 저장소 루트에서 실행합니다.

~~~bash
docker compose up --build
~~~

실행 후 주소:

- 웹: <http://localhost:3000>
- API health: <http://localhost:8000/api/health>
- API liveness: <http://localhost:8000/api/health/live>
- 공개 상태: <http://localhost:8000/api/status>
- OpenAPI: <http://localhost:8000/api/docs>

Compose는 PostgreSQL 16, FastAPI, Next.js 개발 서버를 함께 시작합니다. 로컬에서는 DEV_FAKE_USER가 기본 UUID로 설정되어 플랫폼 로그인 없이도 API를 테스트할 수 있습니다.

### 프런트엔드만 실행

Node.js 22와 pnpm 9.15.4를 사용합니다.

~~~bash
cd frontend
corepack enable
pnpm install --frozen-lockfile
pnpm dev
~~~

웹은 <http://localhost:3000>에서 열립니다. 개발 모드에서 REST /api/*는 BACKEND_URL로 rewrite되지만 WebSocket은 Next 개발 서버를 통과하지 않으므로 ws://localhost:8000/api/ws로 직접 연결됩니다.

### 백엔드만 실행

Python 3.12 이상과 PostgreSQL이 필요합니다.

~~~bash
cd backend
python -m venv .venv

# macOS/Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1

python -m pip install -e ".[dev]"

~~~

.env.example을 .env로 복사해 DATABASE_URL과 로컬 DEV_FAKE_USER를 설정할 수 있습니다.

| 이름 | 용도 | 필수 | 발급·설정 위치 |
| --- | --- | --- | --- |

WebSocket 복구 키가 query에 포함되므로 nginx의 해당 경로 접근/오류 로그를 끄고 Uvicorn 접속 INFO 로그를 비활성화합니다. API 오류는 warning/error 수준에서 확인합니다. 실제 토큰·비밀번호·쿠키는 저장소나 README에 넣지 않습니다. coders.kr 배포 인증은 승인된 로컬 secret 저장소에서만 읽습니다.

기존 데이터베이스를 업데이트할 때는 백엔드 가상환경에서 마이그레이션을 적용합니다.

~~~bash

~~~

## 테스트와 품질 검사

### 프런트엔드

~~~bash
cd frontend
pnpm install --frozen-lockfile
pnpm lint
node --test tests/voice-scope.test.mjs

~~~

pnpm build는 Next.js 정적 산출물 frontend/out/을 생성합니다.

### 백엔드

~~~bash
cd backend
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check app tests
~~~

게임 규칙과 WebSocket만 빠르게 확인하려면 다음을 사용할 수 있습니다.

~~~bash
python -m pytest tests/test_game_flow.py tests/test_ws.py -q
~~~

DB 통합 테스트는 PostgreSQL 고유 기능을 실제로 사용합니다. `TEST_DATABASE_URL`이 없으면 DB 의존 검사만 건너뛰며 이는 전체 통합 검사 통과가 아닙니다. `tests/conftest.py`는 이 값을 앱 import **전** `DATABASE_URL`에도 바인딩해 fixture와 앱의 저장 세션이 같은 대상을 사용하게 합니다.

**DB 테스트는 데이터를 지웁니다.** 각 DB 의존 테스트가 사용자·점수 및 연결된 결과/진행도 테이블을 `TRUNCATE ... CASCADE`로 초기화합니다. 운영 또는 공동 개발 DB를 절대 연결하지 마세요. 아래 문자열의 대문자 항목은 실제 값이 아닌 치환용 자리표시자입니다.

~~~powershell
# 먼저 폐기 가능한 전용 DB를 생성한 뒤 값을 치환합니다.
$env:TEST_DATABASE_URL = "postgresql+asyncpg://TEST_USER:TEST_PASSWORD@127.0.0.1:TEST_PORT/DISPOSABLE_TEST_DB"
$env:DATABASE_URL = $env:TEST_DATABASE_URL
python -m alembic upgrade head
python -m pytest -q
~~~

세션 종료 시 fixture·앱 엔진을 dispose하고 테스트마다 리더보드 캐시도 초기화합니다. GitHub Actions의 PostgreSQL 서비스 역시 전용 테스트 대상이어야 합니다. 마이그레이션 성공, DB API 결과, 게임 단위 테스트와 브라우저 결과는 각각 확인합니다.

### 실제 브라우저 E2E

`backend/tests/browser_server.py`는 일반 `app.main:app` 실행과 분리된 테스트 전용 진입점입니다. 명시적인 `BLACK_MIDNIGHT_BROWSER_TEST=1`과 폐기 가능한 `DATABASE_URL`이 모두 필요합니다. 첫 사건의 시계와 `first-e2e-*` 방의 host 역할 시드만 제어하고, 브라우저 요청은 실제 WebSocket route·권한·게임 엔진을 통과합니다. 테스트 파일은 운영 Docker 이미지에 포함하지 않습니다.

~~~powershell
# 터미널 1: backend/ 에서, 앞서 만든 폐기 가능한 DB만 사용
$env:BLACK_MIDNIGHT_BROWSER_TEST = "1"
$env:DATABASE_URL = "postgresql+asyncpg://TEST_USER:TEST_PASSWORD@127.0.0.1:TEST_PORT/DISPOSABLE_TEST_DB"
python -m tests.browser_server
~~~

~~~bash
# 터미널 2: frontend/ 에서
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
~~~

E2E는 정적 export를 제공하는 로컬 테스트 proxy `127.0.0.1:3100`과 API `127.0.0.1:8000`을 사용합니다. 일반 개발/운영 서버의 시계·역할 RNG를 변경하지 않습니다. 이 결정적 검사는 정상·빈 결과·거절·재전송·단계 변경 같은 재현 가능한 경로의 증거이며 실제 사람들의 토론 재미나 운영 용량 시험을 대신하지 않습니다.

### 반응형·접근성 출시 기준

`360×800`, `390×844`, `768×1024`, `1440×900`에서 홈·입장·밤 행동·증언 대조·투표·종료를 실제로 확인합니다. 가로 넘침, 한 글자씩 줄바꿈, 고정 명령의 가림, 위쪽으로 돌아가는 스크롤, 44px 수준 터치 영역, Tab/Shift+Tab/Enter/Space/Escape·포커스 복귀를 점검합니다. OS light/dark 선호와 reduced-motion에서도 게임의 의도된 다크 테마·입력 상태가 유지되어야 합니다. 빌드 성공이나 캡처 파일 생성만으로 이 기준을 통과한 것으로 보고하지 않습니다.

## 실시간 프로토콜

### 복구·음성 추가 검사

전용 loopback 테스트 DB를 마이그레이션한 뒤 실제 프로세스 종료·재시작을 검사할 수 있습니다. 도구는 자신이 만든 두 API 프로세스만 종료하며 운영 서버에는 연결하지 않습니다.

```powershell
$env:RECOVERY_TEST_DATABASE_URL = $env:TEST_DATABASE_URL
python -m tools.recovery_smoke
node --test tests/voice-scope.test.mjs tests/ws-recovery.test.mjs
```

Python 명령은 `backend`, Node 명령은 `frontend` 디렉터리에서 실행합니다. 부하 발생기·실행 조건은 [CAPACITY_TEST](docs/CAPACITY_TEST.md), 실제 확인한261개 백엔드·19개 Node·8개 브라우저 검사 범위는 [RESILIENCE](docs/RESILIENCE.md)를 확인하세요. 개수를 더해 운영 수용량·무결함·실제 음질을 보장하지 않습니다.

공개 저장소의 무료 표준 GitHub runner에서만 `gh workflow run load-check.yml --ref main -f users=100`으로 최대100명의420초 loopback 검사를 요청할 수 있습니다. 수동 전용이며 실제 운영 URL을 대상으로 하지 않습니다. private 저장소에서는 job을 실행하지 않고 유료/larger runner도 사용하지 않습니다. 이 검사도4만 명·실제 proxy·음성 중계망 검증은 아닙니다.

게임 WebSocket endpoint는 GET이 아닌 다음 주소로 연결합니다.

~~~text
ws://localhost:8000/api/ws?room=<room-code>&nick=<display-name>&key=<resume-key>
# 기존 방 참가에만: &join_only=true
~~~

밤 행동·투표·판결·기록 대조 질문/답변은 `{t, phase_id, ...}`로 요청합니다. `phase_id`는 현재 개인 state에서 받은 값을 그대로 사용합니다. 누락·만료 시 `stale_phase`와 최신 state가 반환됩니다. 기권은 `{t:"vote", phase_id, target:"skip"}`이며 유령 대화는 `{t:"ghost_chat", text}`입니다. 음성 신호는 서버가 보낸 현재 `voice_scope`를 `scope` 필드에 넣습니다. 비밀정보와 접속 복구 키를 로그로 남기지 마세요.

대표적인 클라이언트 → 서버 메시지:

| 메시지 | 설명 |
| --- | --- |
| ready, start, rematch | 준비·게임 시작·재경기 |
| fill_bots, remove_seat, pace | 방장 좌석·속도 제어 |
| action | 밤 역할 능력 대상 선택, 현재 state의 phase_id 필수 |
| chat, react | 공개·비밀 채팅과 빠른 반응 |
| question, claim, read | 질문·공식 진술·신뢰/보류/의심 평가 |
| challenge | `{phase_id,claim_id,clue_id,text}`. 현재 낮의 공식 진술과 공개 기록을 인용하는 라운드당 한 번의 질문 |
| challenge_reply | `{phase_id,challenge_id,text,kind}`. 질문 대상자만 설명(`clarify`) 또는 판단 수정(`revise`)을 한 번 기록 |
| pressure, tip | 긴급 지목과 익명 제보 |
| reveal_lead | 미확인 개인 제보 공개 |
| vote, judge | 용의자 투표와 처형/석방 판결 |
| memory_seal, reconstruct | 첫 인상 봉인과 타임라인 복원 |
| theory | 용의자·감식 단서·개인 시간 조각의 증거 연결 고리 봉인 |
| oath, contract, contract_response | 공개 맹세와 비밀 계약 |
| ghost_predict, ghost_echo, will | 사망자 사후 수사와 유언 |
| voice_presence, voice_signal | 음성 참여 상태와 WebRTC 협상 |

`GET /api/passport`는 로그인한 사용자만 호출할 수 있으며(익명 요청은 401), XP·일일 목표·배지·최근 사건을 반환합니다. 사건 종료 결과는 WebSocket 게임 서버가 내부적으로 기록하므로 클라이언트가 점수를 위조할 수 없습니다.

서버는 연결된 참가자마다 다른 state 메시지를 생성합니다. 마피아 팀 정보, 탐정 조사 결과, 개인 증거와 밤 행동은 권한이 없는 참가자에게 포함하지 않습니다.

새 state에는 공개 가능한 `night_summary`, 인용 snapshot과 답변을 담은 `cross_examinations`, 권한을 나타내는 `me.can_challenge`가 포함됩니다. `night_replay`는 종료 전 빈 배열입니다. `night_summary`는 lobby/reveal/night에 `null`이고 이미 공개된 사망 결과 외의 행동자·역할·습격 대상을 노출하지 않습니다. 명령의 로컬 전송 성공은 접수 완료가 아니며 실제 완료는 해당 state 기록으로 판단합니다. 상세 필드와 실패 경계는 [아키텍처 설계](docs/ARCHITECTURE.md)를 참고하세요.

## 배포

### coders.kr 멀티 서비스 배포

저장소 루트의 coders.yaml이 다음 세 서비스를 정의합니다.

| 서비스 | 이미지 | 역할 |
| --- | --- | --- |
| web | frontend/Dockerfile | Next 정적 export를 nginx로 제공하고 /api·WebSocket을 API로 proxy |
| api | backend/Dockerfile | FastAPI, WebSocket, 게임 룸 상태, health endpoint |
| db | 관리형 PostgreSQL | 사용자·최고 점수·리더보드 저장 |

웹과 API 모두 WebSocket timeout을 3600초로 설정하고, 클라이언트는 재배포·네트워크 단절 시 재연결을 시도합니다. 프런트엔드는 정적 파일이므로 CDN 캐시에 안전하게 올릴 수 있으며, 사용자 identity와 게임 상태는 브라우저/API 통신으로 가져옵니다.

현재 운영 주소:

~~~text
https://black-midnight.coders.kr
~~~

배포 순서는 `boclair98/mafia-game`에 검증된 커밋을 먼저 push한 뒤, `coders-kr/mafia-game` 실제 fork의 `main`을 upstream과 동기화하고, coders.kr 프로젝트 `black-midnight`를 upstream 저장소 URL로 재배포하는 방식입니다. Coders.kr API가 반환하는 `last_deployment.status`가 `ready`가 될 때까지 10~15초 간격으로 확인합니다. 배포 토큰은 로컬 secret 저장소에서만 읽고 출력하지 않습니다.

실제 배포 시에는 먼저 최신 [Coders.kr 지침](https://coders.kr/llms.txt)을 읽고 현재 endpoint·필드를 확인합니다. upstream과 실제 fork의 전체 SHA가 일치하는지 확인한 뒤 배포하며, `ready` 후에도 새 운영 페이지·API·WebSocket·모바일/PC 흐름을 별도로 확인해야 합니다. 배포는 사용자의 명시적 요청이 있을 때만 수행합니다.

배포 전 확인 목록은 [스토어 출시 체크리스트](docs/STORE_RELEASE_CHECKLIST.md)를 참고하세요.

## 현재 한계와 다음 단계

현재 버전은 플레이 가능한 서비스와 핵심 추리 루프, 수사관 패스포트 기반을 제공합니다. 결제는 아직 연결하지 않았으며, 실제 대규모 런칭 전에 아래 항목을 보강해야 합니다.

### 데이터와 확장성

- 단일 실행권을 넘어 다중 API 인스턴스로 방별 분산 실행·라우팅
- 실제 fleet·proxy·DB·음성망을 포함한 수용량/장애 부하 검증
- DB 백업·재해 복구와 무중단 스키마/체크포인트 버전 전환
- WebSocket 연결 수, 방별 phase latency, 오류율 관측 대시보드

### 음성 품질

- 모바일 네트워크를 고려한 TURN 서버
- 대규모 방을 위한 SFU 선택지 검토
- 실제 Android/iOS 기기·통신사 NAT·방화벽에서 미디어 복구/음질 검증

### 안전한 커뮤니티 운영

- 신고·차단 결과의 지속 저장
- 채팅 욕설·개인정보 필터와 rate limit
- 운영자 모더레이션 도구
- 미성년자·음성 채팅 고지를 포함한 스토어 심사 대응

### 게임 콘텐츠

- 사건 프로필과 인과 단서의 지속적인 추가
- 규칙 기반 봇의 전략·설명·밸런스 실사용 검증과 현재 경기 밖의 관계 기억 설계
- 사건 리플레이 공유, 시즌 기록, 외형 중심의 꾸미기 보상

### 수익화 로드맵 (결제 전 단계)

수익화의 전제는 플레이어가 먼저 매일 돌아오고, 친구를 초대하고, 자신의 기록을 자랑할 이유를 갖는 것입니다. 그래서 현재 릴리스에서는 다음 순서만 구현합니다.

1. **지금:** 패스포트·일일 목표·배지·사건 보관소로 반복 플레이와 공유 가능한 기록을 만든다.
2. **다음:** 시즌별 사건 묶음, 프로필 프레임·음성 연출·사건 파일 스킨 같은 외형 인벤토리를 안정적인 ID로 도입한다.
3. **그 다음:** 파티 방장용 편의 기능(커스텀 타이머·리플레이·방 템플릿)을 유료 entitlement로 검토한다.
4. **결제 연동 시:** Stripe/스토어 결제 검증, webhook 멱등 처리, 환불·회수, 구매 복구를 서버에서 구현하고 운영 로그를 남긴다.

역할 능력, 정보 공개, 승률, 매칭 우선권은 판매 대상에서 제외합니다. 가격·상품을 확정하기 전에는 결제 버튼이나 가짜 구매 상태를 노출하지 않습니다.

## 저작권 및 고지

검은 자정은 독립적으로 제작된 소셜 추리 게임입니다. 다른 마피아 게임의 고유 캐릭터·명칭·UI·이미지를 사용하지 않으며, 특정 게임사와 제휴하거나 공식 관계에 있지 않습니다. 사건 현장 이미지는 실제 인물이나 사건을 나타내지 않는 가상 오브젝트 중심 이미지입니다.

프로젝트의 라이선스와 상업적 이용 조건을 별도로 명시하기 전에는 저장소의 이미지·문서·코드를 재배포하거나 상업적으로 이용하지 마세요.

자체 제공하는 Pretendard v1.3.9의 라이선스는 `frontend/public/fonts/`에 포함된 SIL Open Font License 1.1 고지를 따릅니다. 이 서체 고지가 프로젝트 전체 코드·이미지의 라이선스를 대신하지는 않습니다.
