# 연결·경기 복구 설계

2026-11-22 · 구현 및 아래 로컬 검증 완료, 독립 CI·운영 배포는 해당 run/릴리스 보고에서 별도 확인한다. 이 문서는 4만 동시접속 인증이나 TURN 운영 완료 보고가 아니다.

## 이번에 승인된 범위

사용자는 최대 동시접속 4만 명을 장기 목표로 명확히 했지만 별도 서버·TURN·부하 발생기가 없으며, 이번에는 **무료 범위 개선·검증·배포**를 선택했다. 새 유료 자원·계정·예산 충전·운영 사이트 대량 부하는 수행하지 않는다.

실제 끝낼 여정은 연결 끊김 → 같은 좌석으로 재접속 → 서버가 확정한 역할·진행·선택 복구 → 허용된 음성 채널 재연결이다. 저장 전 전송과 저장된 성공을 구분한다.

## 대안과 선택

| 대안 | 판단 |
| --- | --- |
| 브라우저 자동 재접속만 유지 | 프로세스 재시작 때 경기와 좌석이 사라져 제외 |
| 공유 체크포인트 + 여러 프로세스가 각자 진행 | 같은 경기의 상태와 결과가 갈라져 제외 |
| 기존 PostgreSQL + 단일 활성 실행권 + fenced 체크포인트 | 이번 무료 범위에서 선택. 새 브로커 없이 복구와 중복 진행 차단을 먼저 검증 |
| 방 소유자 라우팅 + 분산 게이트웨이·음성 중계망 | 4만 동시접속을 위한 별도 단계. 인프라·예산·분산 부하 검증이 없어 완료로 표시하지 않음 |

단일 실행권은 수평 확장 구현이 아니다. 겹친 프로세스의 standby는 재시도 가능한 `4008 room_recovering`으로 응답한다. 플랫폼이 요청을 standby에 계속 분배하면 가용성이 나빠질 수 있다. 현재 Coders 공개 manifest에는 CPU·메모리·replica·room affinity 조절과 TURN UDP 노출 계약이 없으므로 이 한계를 숨기지 않는다.

## 서버 계약

- 서버 전용 allowlist 기반 versioned JSON에 게임 상태를 보관한다. pickle, WebSocket, Task, Lock, 전송 캐시는 저장하지 않는다. 비공개 역할·개인 단서·좌석 키가 공개 DTO에 섞이지 않게 한다.
- PostgreSQL의 DB 시계 기반 실행권·epoch로 오래된 프로세스의 쓰기를 막는다. join/명령/tick/leave 변경을 방 잠금으로 직렬화하고 저장한 뒤 성공 state를 보낸다.
- 저장 실패 시 마지막 확정 상태로 복원하고 재접속을 요구한다. 처리 성공으로 가장하거나 클라이언트에서 임의로 명령을 재생하지 않는다.
- 서버 중단 동안 놓친 밤·투표를 연속 실행하지 않는다. 마지막 커밋의 단계와 남은 시간을 복원하고 실제 참가자가 복귀한 뒤 재개한다. 조용한 진행 중 경기도 기본5초마다 시계를 저장하므로 마지막 저장 이후의 조용한 시간이 일부 되감길 수 있다.5초는 설정된 주기이지 이벤트 루프·DB 지연까지 포함한 엄격한 오차 상한은 아니다. 새 음성 scope를 사용하고 서버의 음성 참여 상태는 해제한다.
- 경기별 안정된 match ID와 사용자별 중복 제약으로 종료 저장 재시도를 구분한다. 경기 저장과 결과 집계의 실제 트랜잭션 경계·재시도는 테스트로 확인한다.
- 처음 적용하기 전 구 버전이 메모리에만 보관한 경기는 소급 복원할 수 없다. 배포 전 진행 중 경기를 확인한다. 만료된 체크포인트와 DB 자체 유실·손상은 별도의 복구 한계다.
- 진행 중 방의 신규 관전자는 기본12명으로 제한하고 기존 참가자의 복귀는 별도로 허용한다. 관전자만 돌아와서는 멈춘 경기를 재개하지 않는다. 음성은 채널별12명이며 채널이 합쳐질 때 초과 참가자에게 안내한다.

롤백도 호환되는 수정 커밋으로 수행한다. 마이그레이션0003이 적용된 DB를0003 파일이 없는 과거 이미지로 바로 되돌리면 Alembic의 revision 판독이 실패할 수 있다.0003과 체크포인트 판독 호환을 유지하며 필요한 코드를 되돌리고, DB downgrade/삭제·force-push를 사용하지 않는다.

## 음성·브라우저 계약

기존 세션 키를 유지하고 heartbeat, 온라인/화면 복귀, 지터 재시도, 오래된 socket 이벤트 fencing을 적용한다. 일반 게임 명령은 자동 재전송하지 않는다.

음성은 사용자 마이크 의도, 서버의 발언 권한, 연결된 peer, 실제 수신/재생 상태를 구분한다. scope 변경 시 이전 연결을 무효화하고 일시 disconnect에는 유예를 둔다. ICE 재협상/재생성과 자동 재시도는 제한하며 수동 복구 경로를 제공한다.

이미 인증된 게임 WebSocket의 `voice_config` 명령으로 ICE 설정을 받는다. TURN을 설정할 때만 짧은 유효기간의 coturn 호환 자격증명을 발급한다. 공유 비밀을 브라우저·소스·로그에 넣지 않는다. **이번 운영에는 TURN 서버가 없으므로 일부 회사망·통신사 NAT에서 연결이 불가능할 수 있다.** STUN/재시도는 중계망이나 SFU의 서버 강제 미디어 차단을 대신하지 않는다.

## 수용 기준과 검증 층

1. 실제 연결 끊김·재접속 뒤 좌석 ID/역할/단계/확정 행동이 일치한다.
2. 실제 API 프로세스 종료·재시작 뒤 DB에서 상태를 읽고, 경과한 중단 시간으로 단계가 건너뛰지 않는다.
3. 저장 실패·동시 소유권·낡은 epoch·종료 재처리가 미확정 성공, 중복 XP, 비공개 정보 누출로 바뀌지 않는다.
4. 서로 다른 Chromium 문맥의 가상 마이크에서 WebRTC 연결과 실제 수신 RTP 통계를 확인하고 재연결을 검사한다. 가상 음성은 휴대전화·다른 NAT·실제 음질 검증이 아니다.
5. 기존 게임 회귀, 4개 viewport, 키보드·로딩·오류·복구·저장 확인 상태를 검사한다.
6. 로컬 실제 WebSocket 부하는 메모리·시간·동시 수 상한과 중단 조건을 둔다. 실제 달성 수, p95/p99, 실패·누락된 행동 범위를 보고한다. 연결 수 상한 변경이나 단일 장비 외삽을 4만 검증으로 취급하지 않는다.

검사 결과와 운영 배포 식별자는 검증 뒤 기록한다. 자료: [PostgreSQL 16 잠금](https://www.postgresql.org/docs/16/explicit-locking.html), [WebRTC 재협상](https://developer.mozilla.org/en-US/docs/Web/API/RTCPeerConnection/restartIce), [perfect negotiation](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Perfect_negotiation), [coturn 인증 계약](https://github.com/coturn/coturn/blob/master/README.turnserver), [Coders 런타임 계약](https://github.com/coders-kr/template-coders/blob/main/PLATFORM.md). 해당 절을 이번에 직접 읽었으며 제품별 보장을 그대로 확대하지 않는다.

프로세스 검사는 마지막 확정 체크포인트를 복원했다는 증거이며 정확한 장애 순간의 시계를 오차 없이 보존한다는 증거가 아니다. 실제 기기·통신사/회사 NAT·실제 마이크 음질·스크린리더 전체 흐름·4만 동시접속은 이 결과에 포함되지 않는다.

로컬25명/420초 부하는 연결 peak25와 일부 행동/재접속을 관찰했지만 호스트 메모리 guard로 중단돼 전체 통과가 아니다. 앱 누수·처리 한계로 단정하지 않으며 상세 수치와 중단 조건은 [용량 검증 기록](CAPACITY_TEST.md)에 둔다. 같은 도구를 공개 저장소의 무료 표준 Linux runner에서 수동 실행하는 `load-check.yml`을 추가했으며, 실제 완료 여부는 그 run의 결과로만 보고한다. 유료/larger runner·외부 운영 부하·별도 인프라는 사용하지 않는다.
