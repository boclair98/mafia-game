# 2026-11-22 증언 대조실 — 설계·검증 기록

## 사용자 결과와 범위

실제 밤 결과 → 공식 진술 → 공개 기록을 인용한 질문 → 해명/판단 수정 → 투표 → 종료 후 실제 행동 복기를 연결한다. 기능 수와 테스트 개수를 재미·수익·무결함의 증거로 사용하지 않는다.

기준 소스는 `f6964a5eb1e312218e55f338b5cb7469311a12ef`다. 기존 Next.js 정적 export·FastAPI WebSocket·PostgreSQL·역할/FSM·음성 scope를 유지한다. 외부 LLM·결제·새 직업·DB 스키마 변경은 없다. 상세 계약은 [ARCHITECTURE](ARCHITECTURE.md), 시각 결정은 [design.md](../design.md)에 있다.

## 독립 반론과 결정

책임 에이전트와 백엔드 구현·프런트 구현/실화면 검토·별도 품질 검증 에이전트가 분담했다. 내부 에이전트 협업이며 외부 모델·사람 디자이너의 심사나 실사용자 조사가 아니다.

## 타입·배치·표현의 값

Pretendard Variable v1.3.9를 OFL과 함께 자체 제공한다. 본문15px/1.65, 입력16px, 대조 기록14px/1.7~1.75, 제목20~24px, 장면32px, 보조 메타11~12px다. 세리프는 짧은 장면 제목에 제한한다.

1280px 이상은 `232px 역할 | 유동 중심 | 312px 대화`, 열 간격20px다. 아래는 사건/수사/대화/내 정보 탐색으로 바뀐다. 반복 간격4/8/12/16/24/32/48px, 주 조작44px 이상, 패널 반경12px를 사용한다. 이 값은 연구가 보장한 보편 법칙이 아니라 실제 게임 콘텐츠에 정한 값이다.

바탕 `#090d14`, 표면 `#141b25`, 본문 `#f0ece3`, 보조 `#b4bdca`. brass는 선택/행동, blue는 관찰, green은 서버 확인이다. A24의 짧은 장면 위계와 Spotify 공개 앱의 패널 경계를 직접 관찰했지만 자산·브랜드는 복사하지 않았다. 세계 확장 풀의 포트폴리오 예시는 이번 수사 입력 화면의 주 기준으로 승격하지 않았다.

모달의 Tab 순환·Escape·호출 버튼 복귀는 [W3C APG modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)의 해당 동작을 참고했다. WCAG 전체 적합 인증은 아니다.

### 화면·키보드 검사 범위

360×800 /390×844 /768×1024 /1440×900의 캡처를 직접 확인한다. OS light/dark 선호 모두에서 의도된 다크 테마를 유지한다. 별도 라이트 테마는 제공하지 않는다. reduced-motion과 일반 모션을 구분한다.

키보드는 Tab/Shift+Tab의 dialog 안 순환, 중첩 개인정보 안내 닫기와 호출 버튼 복귀, Enter/Space 재진입, 입장 후 설정을 Escape 한 번으로 닫기, 닫힌 뒤 body 잠금 복구를 검사한다. 모바일 메뉴의 활성 상태는 aria-pressed로 전달한다.

E2E runner는 명시적 환경 변수가 필요한 테스트 전용 프로세스다. 첫 사건 seed와 시간을 단축하지만 실제 WebSocket·권한·게임 엔진·DB를 사용한다. 운영 entrypoint에는 fixture가 없고 Docker context에서도 제외한다. 단축 시계 캡처를 운영 템포·8~12분 완주·홍보 이미지의 근거로 재사용하지 않는다.

실제 휴대전화 가상 키보드/IME·iOS Safari·Android WebView, 스크린리더 전체 여정, 200% 글자 확대 전체 기능, 아나운서 음질·실제 마이크 통화는 이 Chromium 결과로 대체하지 않는다.

## 운영·공개·복구 한계

### 서버 시작 준비 검사

기존 production entrypoint는 `/bin/sh`에서 bash 전용 `/dev/tcp`를 사용했다. dash 조건에서는 실제 DB가 준비돼도60회 sleep이 붙을 수 있다. 이를 Python 표준 socket/urlsplit 검사로 바꾸고 즉시 성공·재시도·시간 예산·잘못된 주소·민감 값 비노출·실제 전용 PostgreSQL 연결7개 검사를 추가했다. TCP 연결은 인증/스키마 준비의 증거가 아니므로 Alembic 성공을 다음 gate로 유지한다. DNS와 여러 주소의 해석/연결은 OS 조건이 있어 엄격한 전체60초 상한을 보장하지 않는다.

로컬 Docker가 없어 bookworm 이미지의 전체 entrypoint 실행은 로컬에서 확인하지 못했다. compose의 uvicorn 직접 실행 및 helper 단위 검사와 production 컨테이너의 기동/health를 구분한다. 플랫폼 전체 cold-start 해결이나 항상30초 이내 기동을 주장하지 않는다.

### 의존성 보안 패치

배포 전 npm 감사에서 기존 잠금 파일의54개 advisory(critical7/high24/moderate20/low3)를 확인했다. 이는54개의 실제 운영 공격을 재현했다는 뜻이 아니다. 웹 최종 이미지는 nginx와 정적 out만 제공하므로 Next Node 서버·서버 캐시·이미지 최적화의 노출 조건과 다르다. 빌드 환경과 네이티브 셸까지 무관하다고 결론내리지 않았다.

[Next 공식11월 보안 공지](https://nextjs.org/blog/november-2026-security-release)와 [Capacitor 공식 권고](https://github.com/ionic-team/capacitor/security/advisories/GHSA-rvm3-566m-v7fv)를 읽고 같은 메이저 안의 Next16.4.5 및 Capacitor8.5.1로 갱신한다. 상위 Next가 채택한 Sharp/PostCSS 버전을 사용하며 감사 숫자를 줄이기 위한 무차별 전역 override는 하지 않는다. native sync·네이티브 바이너리 빌드·실기기 검사·스토어 배포는 각각 별도 증거다. npm 감사는 Python/운영 컨테이너 전체 보안 감사를 대신하지 않는다.

최종 `pnpm audit --prod`의 critical/high/moderate/low는 모두0이다. 전체 개발 트리에는 moderate3건(uuid/glob/minimatch)이 남는다. 경로는 Capacitor CLI의 xcode/rimraf 및 eslint-config-next의 TypeScript parser다. 부모가 허용한 범위 안에서는 패치되지 않아 강제 major override를 하지 않았다. 웹 nginx 최종 이미지에는 이 도구들이 포함되지 않지만 비신뢰 프로젝트/입력을 다루는 개발 환경까지 안전하다는 주장은 하지 않는다. CI에 배포용 high 이상 audit gate를 추가했다.

`cap sync android`, `cap sync ios`는 정상 종료했다. Android의 pnpm8.5.1 경로와 iOS SPM exact8.5.1을 직접 확인했다. 실제 Android/iOS 바이너리 빌드·서명·기기 검사는 수행하지 않았으며 기존 설치 앱이 웹 배포만으로 패치됐다고 보고하지 않는다.

- 방과 실제 밤 원장은 프로세스 메모리다. DB의 로그인 결과 요약·점수·XP와 달리 진행 중 경기는 장애 후 복원되지 않는다. 배포 때 경기가 사라질 수 있다.
- 종료 원장은 gameover에서만 공개하며32개 밤/48개 질문의 bounded buffer다. 영구 영상/URL 리플레이가 아니다.
- 같은 Room의 중복 종료는 막았지만 프로세스 장애와 DB 커밋을 아우르는 exactly-once 이벤트는 아니다.
- P2P 음성은 TURN/SFU가 없어 일부 네트워크에서 실패할 수 있다. 악성 클라이언트의 미디어를 서버가 강제로 차단하는 SFU 구조가 아니다.
- 4만 명 수용량, 수익성, 실제 재미·재방문, 장기 AI 학습·자연어 LLM은 미검증/미구현이다.
- 롤백은 이전 소스로 새 commit을 만들어 upstream→fork→재배포한다. force-push·운영 DB 삭제를 사용하지 않는다. 이번 기능은 새 DB 마이그레이션을 요구하지 않는다.

Git과 Docker context에서 `.env`·`.coders`·DB·키·로그·브라우저 trace/보고서를 제외한다. 작업 파일과 Git 이력의 고신뢰 토큰/개인키 패턴 검사 및 새 파일/staged diff 검토는 모든 비밀·취약점 부재 보장이 아니다.

배포는 최신 coders.kr/llms.txt와 기존 black-midnight 프로젝트를 사용한다. canonical push→실제 coders-kr fork의 main 전체 SHA 일치→배포→새 운영 UI/기능 확인 순서이며 API 접수와 ready, 실제 사용자 여정을 구분한다.
